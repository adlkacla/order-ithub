# Проект:

OrderHub — консольное приложение на C# для учёта заказов интернет-магазина. Программа принимает и обрабатывает заказы, позволяет отменить последнее действие и хранит историю заказов каждого клиента. Ещё в ней есть учёт товаров на складе (поступление и продажа) и сортировка каталога по разным критериям. Приложение строит отчёты: дорогие товары, сводку по категориям и топ-3 клиентов. Заказы можно выдавать постепенно, по одному, а последние заказы хранятся в собственном кольцевом буфере. Всё управление идёт через консольное меню.

## Вопросы:

1. Чем Queue<T> отличается от Stack<T> и когда применяется каждый?

* `Queue<T>` работает по принципу FIFO (первым пришёл — первым ушёл), а `Stack<T>` работает по принципу LIFO (последним пришёл — первым ушёл)

2. Зачем сохранять узел, возвращённый AddLast, вместо повторного поиска через Find?

* `AddLast` сразу возвращает `LinkedListNode<T>`, поэтому вставка относительно него (`AddAfter`/`AddBefore`) выполняется за O(1). `Find` проходит список линейно, за O(n). Кроме того, `Find` сравнивает элементы по значению и при дубликатах может вернуть не тот узел.

3. Почему попытка прочитать отсутствующий ключ словаря через индексатор приводит к исключению, и как этого избежать?

* Индексатор `dict[key]` должен вернуть значение. Если ключа нет, вернуть нечего, а «значение по умолчанию» нельзя отличить от реально сохранённого. Поэтому выбрасывается `KeyNotFoundException`. Чтобы этого избежать, используйте `TryGetValue(key, out var value)`, предварительную проверку `ContainsKey` или `GetValueOrDefault`.

4. В чём разница между IComparable<T> и IComparer<T> и что произойдёт при Sort() типа без обоих интерфейсов?

* `IComparable<T>` задаёт «естественный» порядок внутри самого класса (метод `CompareTo`), и такой порядок у класса один. `IComparer<T>` — внешний класс-сравниватель (метод `Compare`), таких можно сделать сколько угодно, например по цене, по названию или по длине названия. Если вызвать `Sort()` без аргументов для типа, который не реализует ни один из интерфейсов, будет выброшено `InvalidOperationException`: не удаётся сравнить элементы.

5. Что такое отложенное (ленивое) выполнение LINQ-запроса и когда реально происходит обход?

* Методы вроде `Where`, `Select` и `OrderBy` не выполняют запрос сразу. Они только строят его описание. Реальный обход происходит при перечислении: в `foreach` или при вызове материализующих методов `ToList`, `ToArray`, `Count`, `First`, `Sum` и т. п. Каждое новое перечисление выполняет запрос заново на актуальных данных.

6. Чем отличается IGrouping<TKey, TElement> от обычной коллекции и какие операции к нему применимы?

* `IGrouping` — это последовательность `IEnumerable<TElement>`, у которой есть дополнительное свойство `Key`: общий ключ группы. Индексатора и методов изменения у неё нет. К группе можно применять `foreach` и любые LINQ-операторы: `Count()`, `Average()`, `Sum()`, `Max()`, `Select()` и т. д. Например, «количество и средняя цена по категории».

7. Как работает Join и что произойдёт, если у одного клиента несколько заказов?

* `Join` — это внутреннее соединение: для каждой пары элементов, у которых совпали ключи (например, `order.CustomerId == customer.Id`), формируется результат. Если у клиента несколько заказов, он попадёт в результат несколько раз, по разу на каждый заказ. Клиенты без заказов в результат не попадут. Чтобы собрать заказы каждого клиента в одну группу, используют `GroupJoin` или `GroupBy` после `Join`.

8. Почему бесконечный итератор не приводит к зависанию программы, а Take(N) ограничивает его работу?

* Итератор с `yield return` ленивый. Каждый элемент вычисляется только по запросу (`MoveNext`), после чего выполнение приостанавливается до следующего запроса. `Take(N)` запрашивает ровно N элементов и прекращает перечисление, поэтому бесконечный цикл внутри итератора дальше не выполняется.

9. Зачем нужна явная реализация IEnumerator IEnumerable.GetEnumerator() в собственном классе коллекции?

* `IEnumerable<T>` наследует необобщённый `IEnumerable`, поэтому класс обязан реализовать оба метода `GetEnumerator()`. Сигнатуры у них отличаются только типом возвращаемого значения. Необобщённую версию реализуют явно, и она просто возвращает обобщённую. Так у класса остаётся один публичный типизированный `GetEnumerator()`, а коллекция при этом совместима со старым кодом, которому нужен `IEnumerable`.

10. Как в кольцевом буфере определить индекс самого старого хранящегося элемента?

* Если буфер ещё не заполнен (`count < capacity`), самый старый элемент лежит по индексу `0`. Если заполнен, он находится на позиции, куда будет сделана следующая запись: `head` (индекс следующей записи). В общем виде: `(head - count + capacity) % capacity`. Элемент номер i по возрасту находится по индексу `(start + i) % capacity`.

11. Чем готовый проект с девятью этапами лучше девяти отдельных заданий?

* Темы связаны общим сюжетом и общими данными, и видно, как коллекции, LINQ и итераторы работают вместе в одном приложении. Проект учит поэтапной разработке: ветки, коммиты, Pull Request'ы, постоянная компилируемость кода. Каждый новый этап опирается на код предыдущих, поэтому приходится писать поддерживаемый код. В итоге получается целостная программа для портфолио и читаемая история изменений в Git.
